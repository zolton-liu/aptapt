## Frozen hypothesis

The v6.7 validated finance operators improved the first six observed tasks, but
their trajectories still wasted model calls on actions that could not advance
the current state. The v6.8 change makes tool affordances state-dependent:

- a required-operator task without `scratch/solve.py` permits only a complete
  `write_file` bootstrap;
- reads, edits and execution of a missing solver are controller-policy errors,
  not implementation or method failures;
- after a real operator-adapter execution failure, repair must use the current
  solver and execution evidence instead of restarting workspace exploration;
- `copy_file` is limited to Python templates, and non-code inspection artifacts
  do not reset no-progress tracking.

The frozen prediction is that these changes reduce pre-draft and repair-loop
waste without changing the validated numerical operators. This is an overall
framework regression, not a component isolation experiment.
