## 1. 三层验证：执行检查，而不是填写通过标志

`src/qfa_agent/verification.py` 提供 `AuditReport`。必须同时覆盖结构、计算、交叉检查；少一层不能算通过。检查函数实际执行后生成带结果、证据、适用范围的记录，普通手写 `Check(..., passed=True)` 不被接受。这不是防恶意 Python 的安全边界。

| 层次/领域 | 已实现的检查 | 不能据此宣称什么 |
|---|---|---|
| 结构 | 必要字段、实际类型、数组形状；写出后重新读取 JSON/CSV 验证文件、字段、列序、数值类型 | 模型声明的 schema 一定正确；任意文件格式都支持 |
| 计算 | 数值有限、带标签索引一致且唯一、相关矩阵约束 | 单凭无 NaN 就证明算法正确 |
| 回归交叉检查 | 通过逐行标量求和，从 X 和系数重新计算预测与残差，检查标签 | 系数一定是最优解、因果假设成立 |
| 回测交叉检查 | 独立重放带方向成交和费用，重算每时点现金、持仓权益 | 自动支持拆股、分红、外部现金流、保证金或衍生品结算 |
| 风险交叉检查 | 排序损失样本，按明确指定的分位数与 ES 口径重新计算 | 不同尾部口径等价、可以自动变更期限或损失符号 |
| 定价交叉检查 | 三档网格细化差异与给定边界参考比较 | 三档结果就证明渐近收敛、声明的边界一定适用于当前产品 |

不在上述适用范围的任务可使用单独编写的参考函数进行数值比较，但报告明确标注：参考函数由模型编写，其独立性与正确性尚未经过框架审定，不能与内置重算器混为一谈。JSON/CSV 深检查有 8 MB 文件上限；其他格式需要扩展验证器，当前不静默放行。

阶段顺序仍是 `load_inputs → compute → audit → write_outputs`。失败记录包含本次运行 ID、求解源码哈希、失败阶段和验证器哈希；验证失败会阻止后续写出阶段。写出后还检查实际文件，避免仅验证内存中的结果对象。

### 严格模式

新实验应明确设置 `QFA_VERIFICATION_REQUIRED=1`，参考隔离目录的 `configs/verification-v63.env.example`。严格模式要求当前版本的阶段验证与写出检查均通过：删除 `QFA_VERIFICATION` 标记、返回旧版布尔字典、直接写文件、预算结束兜底、修改代码后复用旧证据，都不能满足完成门槛。旧版兼容模式仍保留，不能称为通过三层验收。

阈值、边界、交易约定与输出 schema 仍须从题目推导。目前“不能为了通过而放宽阈值”是明确的求解策略约束，尚非外部锁定任务规格的形式化证明。

## 2. 实现失败与方法复核分流

`workflow.py` 新增 `implementation / method_review / undetermined` 反馈路线。

- 路径、字段、维度、未定义变量等证据，指向实现修复。
- 结构化网格细化或边界失败，触发方法复核；仍须排除实现错误，不把诊断建议当作确定根因。
- 普通 NaN、超时或未知异常不足以确定方法失败，保留未判定状态。

`revise_method` 工具记录“根因假设 → 支持证据 → 一个拟议改变 → 可证伪的检查”，连同源码哈希写入任务内方法计划。记录计划不等于修复成功，不清除失败门槛；后续必须修改实现并重新验证。当前没有自动选择任意新算法，也没有把收益差一概判定为代码错误。

上下文只保留有限的失败证据和最近方法计划，详细证据留在轨迹、阶段记录及 `scratch/.agent/method-plan.json`，避免把完整反思历史不断堆进提示词。

## 3. 跨任务经验：有适用条件的已验证规则

新增 `experience.py` 与 `experience_rules.py`。在线求解只读任务开始时冻结的经验，不将反思自动晋升。离线流程为：

`candidate → reproduction_verified → variant_regressions_passed → verified`

任一验证失败则拒绝晋升。检索同时核对规则内容、规则源码哈希、语义哈希、全部用例记录、任务类别和当前错误类型；原始未验证观察不直接注入后续提示词。当前只实现了一条经代码审阅定义的日期键对齐规则，不是任意反思文本都能进入长期库。

### 日期对齐规则

记录内容包括适用条件、错误现象、待验证根因、修复方法、验证方式、不适用情况。仅当任务规定日期交集、唯一日期键，并允许所选列共同删除缺失样本时，才适用按日期交集和共同缺失掩码对齐；不能靠截断到相同长度消除异常。

已实际运行的五个用例：

1. 合成 2516/2515 行错误复现，检查修复后的日期与数值，并证明截断会错配。
2. 缺少一天。
3. 日期乱序。
4. 重复日期必须拒绝，不能自行去重。
5. 两侧缺失位置不同。

这组证据是合成最小复现，不是此前 Fama–French 原题轨迹的完整复现。因此记录仍保留 `actual_task_cause_verified=false`；只能说该规则通过列出的用例，不能说原题根因已查明。

经验位于隔离目录 `knowledge/verified-experiences/date-key-intersection-v1.json`。需要通过 `QFA_EXPERIENCE_DIR` 显式启用；未指定时不读取长期经验。新评测 runner 会复制经验快照并登记其哈希，整个实验使用同一副本。此模式拒绝自动 resume，避免未经完整溯源检查混接实验。

## 4. 验证结果与后续实验

- 完整工程测试：157 项通过（原有 139 项 + 新增 18 项）。包括真实子进程的审计失败阻止写出、修复后通过，以及严格模式和预算结束绕过回归测试。
- 经验晋升：五个列明的复现/变体均通过，状态 verified；仍限定合成证据范围。
- 87 题初始上下文预检查均在 16000 预算内；最大估算 13029。使用 UTF-8 字节启发式，不是模型实际 tokenizer 计数，也不保证后续所有错误轨迹都能装入。
- 未测新的 pass@1，也未训练模型权重或实施 RL。

待当前 v6.2 实验完成、结果封存后，再将候选版切入新实验。为了区分贡献，建议先比较“旧版 / 严格验证 / 严格验证加已验证经验”，冻结相同模型、题单、预算和评分器；不要对失败题重跑择优。已知公开集的改进不能宣称为官方隐藏集泛化提升。

## 参考思想

[RD-Agent(Q)](https://arxiv.org/html/2505.15155v2) 将研究假设、实现和实验反馈组织为迭代过程；这里借鉴职责分离，以单模型状态和证据记录实现，没有复制其多 Agent 数量。

[Reflexion](https://arxiv.org/html/2303.11366v4) 通过语言反馈与情节记忆影响后续决策，而不是直接更新模型权重。本实现额外加入规则适用范围、实际回归验证和受控晋升要求；这些额外机制是本项目设计，不应归因于论文已经证明。
