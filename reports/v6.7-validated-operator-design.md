# v6.7 validated-operator design

Date: 2026-09-24

## Objective and evidence

The frozen v6.6 fixed-ten baseline passed 2/10 tasks. The main failure pattern was
not a lack of further free-form reflection: long generated implementations lost
the output contract, introduced syntax/path/shape errors, or completed a
calculation without finishing the required artifacts. v6.7 therefore introduces
small model-written adapters around tested, task-family operators for five of the
failed families.

The operators cover:

- geometric mean-reverting jump diffusion;
- Fama--French three-factor estimation with Newey--West inference;
- closed-form implied-volatility approximations;
- variance-swap replication from a dirty option chain; and
- American-option Crank--Nicolson/PSOR pricing.

This is an overall architecture change, not a component ablation. Any later score
must be reported as a fixed-list local public-set result, not as evidence of
official hidden-set generalization.

## Verification architecture

Each operator owns its complete compute-and-write transaction and checks three
separate evidence classes before publishing artifacts:

1. **Structure:** required rows, fields, files, types, counts, and array shapes.
2. **Calculation:** finite values, aligned date indexes, option repricing,
   finance inequalities, matrix/covariance conditions, and convergence.
3. **Independent cross-check:** reconstructed regression residuals, analytic
   versus seeded Monte Carlo moments, Black--Scholes repricing of inverted
   volatility, P&L identities, or coarse/fine Richardson comparison.

The controller detects the exact task family from the safe instruction. In local
compatibility mode it accepts only one top-level call to the required operator,
in a short script with no function/class/loop definitions. The controller
previews `write_file`, `replace_text`, `replace_lines`, `replace_function`, and
`copy_file` candidates, so a valid adapter cannot later be expanded into an
unchecked reimplementation through a repair action. Strict staged mode retains
its compute/audit/write wrapper and final publication gate.

## Engineering verification before evaluation

- Python compilation succeeded for all changed modules.
- The complete repository test suite passed.
- Direct public checker validation passed for all five added workflows:
  geometric jump diffusion 34/34, Fama--French 101/101, implied volatility
  10/10, variance swap 17/17, and American finite differences 54/54.
- The default American-option bundle completed in approximately 25 seconds on
  the local machine.

These are implementation/contract checks and are **not** counted as pass@1.
Strict pass@1 will be measured once on the preregistered ten-task list with the
pinned local model and no selection or rerun of failed tasks.

## Sources and contamination boundary

The mathematical conventions and public expected contracts were checked against
the organizer's public Track 1 repository at commit
`3f6a7a6bd37c2fc0d59eb94b609f1098a42a9bc0` and the public
[QuantitativeFinance-Bench repository](https://github.com/QF-Bench/QuantitativeFinance-Bench),
which is distributed under CC BY-NC 4.0. The implementation is integrated as
parameterized operators with independent validation rather than copied into
model prompts as fixed answers. No contamination banners, canary identifiers,
raw data, or raw evaluation traces are committed.

Because these tasks and checkers are public and were used during development,
the resulting ten-task run is a known-public-set regression test. It must not be
presented as an unbiased benchmark estimate.
