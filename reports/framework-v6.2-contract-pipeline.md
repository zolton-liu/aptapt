# v6.2：输入契约、准确修复定位与分阶段执行

2026-09-23。本轮是在 v6.1 的代码上继续修改，没有改模型权重、评分规则、公开任务数据或历史结果，没有新增运行依赖。**尚未产生 v6.2 的真实模型 pass@1；v6.1 的 2/10 不能作为本版成绩。**

## 1. 输入和领域检查从文字建议变为可执行函数

新增 `src/qfa_agent/contracts.py`，由生成的 Python 求解器调用：

| 检查 | 执行行为 | 刻意不做的事 |
| --- | --- | --- |
| input_path | 要求输入清单里的确切相对路径、文件存在、通过既有工作区可见性检查 | 不猜 basename，不自动替换同名文件，不开放 verifier/reference |
| json_object | 按元组键路径检查配置字段与类型，区分标量和字典 | 不把浮点值变成字典；不把布尔值当整数 |
| require_columns | 检查必要列和列名唯一性 | 不静默重命名列 |
| require_aligned | 检查索引唯一、顺序及标签完全一致，而非只比长度 | 不截短数组，不擅自决定 inner/outer join |
| require_finite | 在写出前拒绝非有限数值 | 不填零、不允许 NaN 伪装成结果 |
| require_correlation | 风险任务的相关矩阵：方阵、对称、单位对角线、范围、半正定 | 不擅自投影修复矩阵，不用于协方差矩阵 |
| require_price_bounds | 定价任务：按显式提供的上下界检查价格和形状 | 不把普通股票看涨期权界限套到所有产品 |
| require_accounting | 回测任务：相同形状的现金、持仓市值、权益对账 | 不自动修正账本或费用 |

字段、清洗规则和金融边界仍需根据任务说明确定。原始脏数据可以按任务要求清洗后再检查，不能把清洗任务变成“遇到脏数据直接拒绝”。这些检查不会自动推断全部业务约束；模型没有调用的检查不会被假称为已执行。

## 2. 修复位置不再混用库文件与求解脚本行号

旧 `_postprocess_python_outcome` 取 traceback 最后一个行号，却固定到求解脚本读取。当最后一个栈帧属于 pandas 等库时，就可能拿库里的第 873 行去读取短求解脚本，造成空白或错误定位。

新 `repair.py`：

- 只选择 traceback 中真实属于 scratch/output 的 Python 栈帧；支持辅助脚本，不把 helper.py 的错误映射成 solve.py。
- 同时记录虚拟路径、行号、源码哈希、失败表达式和相关变量的定义/使用位置。
- 优先保留出错行片段，再补相关引用，避免较长上下文挤掉真正的故障位置。
- 路径错误只列出可见输入清单中的同名候选，不自动选一个路径替换。
- 找不到可信的自有代码栈帧时明确报告无法定位，不猜行号。

这能针对“修了直接读取路径，却遗漏传给算子的 data_path”提供更完整的证据。它是有限的语法引用分析，不是完整数据流分析，也不声称知道运行时变量值。

## 3. 记忆绑定当前源码，旧错误不冒充当前错误

- 已生效的源码修改把相应旧错误标为 stale，含被 traceback 指向的辅助脚本；这不等于错误已解决。
- 实际重新执行后，旧的被拒绝编辑提案移入历史，不再与当前 traceback 并列为当前故障。
- 重放旧执行证据不被计为一次新执行失败，也不能清除失败门槛。
- 只有同一个执行/测试/输出检查成功才更新为 resolved；其他脚本成功不能替代。
- 检查点只保留一份主要修复片段，历史记录去除重复大片源码。大观察仍落盘，模型看到有界的结构化预览。

没有新增跨题答案记忆、向量检索或自动训练。

## 4. 新求解器可以执行真正的四阶段协议

新增 `stages.py`，在 `runtime.py` 中调用。新求解器声明 `QFA_STAGED = True`，定义：

1. `load_inputs()`：返回检查后的输入字典。
2. `compute(inputs)`：返回结果字典。
3. `audit(inputs, result)`：返回根据实际数值计算的、有名称的 Python bool 检查。
4. `write_outputs(result)`：前三步完成后写出交付物。

运行器依次调用，每一步失败即停止；缺失函数、空检查、字符串形式的真假值、不通过的自检均不能进入正常写出阶段。即便程序以 `SystemExit(0)` 提前退出，阶段未完成也不能被记作执行成功。

一次脚本执行完成四阶段，不额外消耗四轮模型调用。不复用旧中间结果，不因源码改变而继续使用旧阶段证据。证据存于 `scratch/.agent/stages/<run-id>.json`，绑定本次运行 ID 和入口脚本哈希；源码改动后控制器把旧阶段记录标为过期。该哈希不覆盖全部导入依赖。

各类别调用不同的可执行检查：因子任务优先索引对齐，风险任务检查相关矩阵，定价任务检查合同边界，回测任务核对账本；它们不再只是不同的“架构名称”。具体计算算法和独立金融校验仍由求解器根据任务实现。

兼容范围与边界：

- 新编写、非预置算子适配的求解器会收到四阶段协议提示。现有金融算子适配器、修复迁移模板继续走 legacy 路径，不强行重新实现已有计算。
- 未声明阶段协议的旧脚本仍可运行，但日志明确标为 legacy，不宣称已通过阶段检查。
- 阶段自检由模型编写，不等于官方 checker；恒真检查可能没有价值，框架无法仅凭布尔结果证明金融正确性。
- 这是执行协议，不是新的安全沙箱。任意顶层代码仍可能产生副作用；协议禁止在阶段外写出，但没有声称能隔离恶意 Python。
- 现有输出校验和失败执行门槛保留，最终 reward 定义未改。

## 6. 后续可做单组件对照

新增三个独立环境开关，默认均开启，runner 将其记录进新 run_config：

- `QFA_STAGE_PIPELINE=0`：关闭新阶段提示及运行调度。
- `QFA_REPAIR_CONTEXT=0`：关闭新的结构化修复定位包。
- `QFA_VERSIONED_MEMORY=0`：关闭新增的版本失效和主要修复证据存储逻辑。

这些开关用于同一 v6.2 公共代码上的消融，不声称“全关”等同于历史 v6.1 源码。它们并非完全统计独立：例如修复包需要工作记忆保存才能跨轮保留，必须考虑组件交互。

建议下一轮保持模型、固定 10 题、18 步、900 秒和 starter=false 不变，以新的唯一实验名做对照；逐题保留失败，不重跑择优。应同时统计阶段采用率、故障位置是否可定位、反复修同一错误次数及严格 pass@1。有效后再推广到新版本完整 87 题。
