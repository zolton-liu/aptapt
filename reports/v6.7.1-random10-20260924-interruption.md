# v6.7.1 fixed-ten evaluation interruption report

Date: 2026-09-24

Experiment: `workflow-v6.7.1-readonly-random10-20260924-coder14b`

## Terminal status

The new experiment stopped during checker staging for its first task. It has no
`results.jsonl` row and is not a pass@1 measurement. The first Agent rollout is
preserved with its trajectory, metrics, solver, and four generated artifacts;
the other nine tasks were never started. The experiment will not be resumed,
overwritten, or combined with another run.

The first Agent itself completed successfully in 112.293 seconds with five
model calls and `starter_used=false`. The checker did not execute, so the task
has no score.

## Root cause

The v6.7.1 isolation change correctly removed write bits from frozen input files.
`stage_checker` then copied the frozen `checks/` directory into the private
per-task verifier workspace. `shutil.copytree` preserved the read-only mode of
`test_outputs.py`, but the runner must rewrite container mount paths in that
private copy before executing pytest. Its `Path.write_text` therefore raised
`PermissionError`.

The frozen task input remained unchanged. This is a local runner staging defect,
not an Agent/checker failure and not an upstream data change.

## Corrective action

Before rewriting each Python checker in the private verifier workspace, the
runner now adds the owner-write bit to that copied file only. The source input
snapshot remains read-only. A regression test stages a read-only checker,
verifies both output/data path substitutions, and confirms the source checker's
bytes and read-only mode are unchanged. Targeted runner tests and the complete
repository test suite pass.

Any subsequent complete ten-task evaluation requires a new experiment name and
explicit user authorization; no row from this interrupted run may be reused.
