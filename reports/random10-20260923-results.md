## 失败轨迹与问题

### 1. 防重复机制拦截了动作，但未让 Agent 有效换策略

轨迹累计出现 42 次重复读取被阻止、17 次未修改失败脚本的重复执行被阻止、12 次完成操作被最终校验门禁阻止。它们是事件数，不是独立失败题数，部分错误事件可能嵌套记录。模型仍持续请求已被阻止的动作，消耗调用与时间，最终 9 题触及 900 秒上限。

### 2. 文件路径、数据结构与代码修复仍不稳定

- 财报惊喜计算题先使用错误输入路径，随后局部修复产生缩进错误，并陷入重复读取。
- 方差互换题对浮点数进行下标访问，产生 `TypeError`；随后行级替换又产生意外缩进。
- 亚洲期权题曾使用错误文件路径；后续脚本把 Agent 的 `write_file` 工具当作 Python 函数调用，产生 `NameError`。虽然此前已写出正确输出，Agent 仍未成功结束。
- 汇总中有 21 次 `run_python` 程序失败事件，以及写入或替换后的自动运行失败和语法验证失败。需要先解决工具调用与修复可靠性，不能把全部失败简单归因于金融知识不足。

### 3. 上下文预算合规，不代表上下文有效

155 条上下文请求中，最大估算长度为 15988，未超过 16000；9 条请求发生历史裁剪，15 条请求记录了非零 observation offload 状态（不是 15 次独立卸载）。未见 `ContextBudgetError`。

预算控制确实工作，但没有阻止重复行为与修复循环。上下文/记忆设计是否导致下降，仍需受控消融实验验证；本轮不能建立因果结论。

## 后续建议（本次未执行）

1. 优先让重复失败触发明确的策略切换或安全结束，而不只是返回拦截消息；为验证与结束保留时间预算。
2. 强化输入路径与 JSON 字段类型探查；局部代码编辑失败后，采用带语法检查的完整函数/文件修复，避免连续破坏缩进。
3. 区分 Python 函数与 Agent 工具；将“已有合格产物但仍无法结束”纳入专门回归测试。不能靠事后修改评分规则美化本轮结果。
4. 固定模型、题单与预算，对上下文裁剪、记忆注入、防循环恢复分别做消融，再扩大到 87 题。仅有 10 道已知公开题，不足以证明泛化提升；暂不把 RL 当作优先补救措施。
