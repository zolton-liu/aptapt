## Root cause

The local runtime creates convenience aliases in scratch for uniquely named
input data files. `scratch/prices.csv` was a symbolic link to the frozen DCC
input snapshot. The generated solver was derived from the supplied data-fetch
helper and used its own directory as an output location. Its write to
`prices.csv` therefore followed the alias and replaced the input snapshot's
header (`AAPL,MSFT,JPM,JNJ,XOM`) with repeated `Close` columns.

The runner's post-Agent integrity gate detected that
`environment/data/prices.csv` no longer matched the launch manifest and stopped
the whole batch with `input/checker drift detected`. The organizer public source
remained unchanged and still matched the pre-run manifest. This was a local
input-isolation defect, not upstream checker drift.

## Corrective action

The local snapshot creator now removes all write permission bits from every
frozen input file after verifying its content hash, while preserving executable
bits. A regression test creates the same scratch-to-input data symlink and
confirms that an attempted write raises `PermissionError`, leaves the bytes
unchanged, and passes the manifest audit. Targeted runner/workspace tests and the
complete repository suite pass after the change.

A new complete evaluation, if authorized, must use a new experiment name and a
new preregistration. It may not copy or count any row from this interrupted run.
